# CA (ICAI) content — schema and learning flow

StudyVerse's professional-course track for **Chartered Accountancy (ICAI)**. The UI is `js/ca.js`
(pro look band, `html[data-age=pro]`); content lives here.

## Copyright rule
ICAI study material is copyrighted. We follow its **structure and scope only** — level → paper →
module/part → chapter → unit → ICAI topic headings, titles and order exactly as ICAI — but every
explanation, analogy, example, illustration, figure and question is **original**.
`tools/ca_validate.py --src <ICAI text folder>` fails if any 10 consecutive words match the ICAI text.
Sections of Acts and case names are cited, never copied as long quotations.

tools/ca_src/                    unit sources in Python; every figure is computed  (python3 tools/ca_src/build.py)

```
Workflow for a new unit: write `tools/ca_src/fnd_pX_chYY_uZZ.py` → add the id to `BUILT` in
`tools/ca_build_structure.py` → run the builder, `tools/ca_src/build.py`, then `tools/ca_validate.py --src …`
→ add the JSON to `CORE` in `sw.js` for offline use.

      "pattern": {"mode": "descriptive|objective", "marks": 100, "hours": 3, "negative": 0.25, "note": "…"},
      "sections": [{"key":"A","name":"Income-tax Law"}],          // papers split into sections (Inter P3, P6)
      "chapters": [ { "id": "fnd-p1-ch02", "n": 2, "title": "Accounting Process", "module": "Module 1", "part": "Part A: …", "sec": "A",
          "units": [ { "id": "fnd-p1-ch02-u01", "n": 1, "title": "Basic Accounting Procedures – Journal entries",
                       "topics": ["Double Entry System", "…"],        // ICAI section headings (Foundation)

```
Ids: `<fnd|int|fin>-p<N>[-<sec>]-ch<NN>-u<NN>`; `sec` is used where ICAI restarts chapter numbers
(e.g. `int-p3-b-ch01` GST, `int-p2-ii-ch01` Other Laws, `fin-p5-ii-ch01` Customs). Ids are permanent —
progress, MCQ stats and saved answers are keyed on them.

## Unit file (`"schema": "ca-unit/1"`)
| key | content |
|---|---|
| `id, level, paper, chapter, n, title` | identity (must match structure.json) |
| `outcomes[]` | learning outcomes in our own words (2+) |
| `meta` | `difficulty` core/moderate/hard · `minutes.learn` · `minutes.practice` · `prereq[]` · `exam_tip` |
| `concepts[]` | `id, title, body[] (paragraphs), blocks[] (optional), analogy, work` ("Why it matters in real CA work") |
| `illustrations[]` | `id, title, difficulty, minutes, q, given[]?, solution[] (blocks), checks[]` — exam presentation format |
| `jobs[]` | "On the job": `id, title, role, situation, steps[], takeaway, think?, answer?, checks?` |
| `mcqs[]` | `id, q, options[4], answer (index), explain, concept, topic, difficulty, check?` (UI shuffles options). `topic` = one of the unit's structure.json `topics` or one of its concept-card titles (exact text; case, spaces and dash/quote variants ignored); `explain` 35+ words. Both are validator warnings now, errors with `--strict` |
| `questions[]` | descriptive: `id, marks, minutes (≈1.8/mark), difficulty, pad, q, given[]?, model[] (blocks), scheme[], remarks[], mistakes[], tips[], checks[]?` |
| `revision` | one-page: `summary[], remember[], traps[]` |
| `quickref[]` | formula / section quick reference: `{k, v}` |
| `viva[]` | 5+ "speak & revise" questions: `id, q (read aloud), model (spoken model answer), concept?, points[]` — see below |
| `cases[]` | 1+ case-study MCQ sets: `id, title, difficulty, case (text), given?[blocks], mcqs[3–5]` (same MCQ fields; ids unique in the unit) |

### Viva key points (`viva[].points[]`)
`{id, pt, w, kw[], min?}` — `pt` is shown to the student, `w` is an integer weight, `kw` is a list of keyword
groups (`"debit|dr"` = synonyms; an alternative may be a short phrase), `min` = groups needed (default all).
Matching is offline and identical in `tools/ca_vivamatch.py` and `js/ca-tools.js`: lower-case → abbreviations
(Dr, Cr, A/c, ₹, &, u/s, lakh/crore → digits) → stop-words dropped → light stemming; a phrase matches when its
words appear in order at most 2 words apart; words match on equality, a long shared stem, or one-letter slips
(6+ letters); numbers within 0.5%. Score = weight covered ÷ total weight; ≥ 80% = "viva-ready".
The validator proves every model answer scores 100%, that reading the question back scores < 80%, that no
keyword is only stop-words, and that the JS and Python matchers agree (needs `node`).
Sources: `tools/ca_src/ca_viva.py`, `tools/ca_src/ca_cases.py` (merged into each unit by `build.py`).

## Mock papers (`content/ca/<level>/mocks/<id>.json`, `"schema": "ca-mock/1"`)
`id, level, paper, title, label` (must say "not an ICAI paper"), `scope, hours, marks, compulsory[], choose, rules[], questions[]`.
Question: `{id: "Q1", marks, parts[]}`; part kinds: `tf` (`items[{id, s, answer: bool, reason}]`, 2 marks each —
2 marks only for a correct verdict with a correct reason; verdict checked automatically, reason self-checked), `ref` (`"unit#qid"` from a unit's question bank; marks must match),
`q` (a new question with the unit-question fields). Validator: parts add up, compulsory + `choose` × optional = paper marks.
Source: `tools/ca_src/mock_*.py`. Pattern for Foundation Paper 1 taken from ICAI model test papers (Q1 compulsory,
any four of the remaining five, 3 hours, 100 marks).

`scheme[]` = ICAI-style step marks: `{id, pt, m, skill}`; marks must add up to `marks`; half marks allowed.
`skill` ∈ posting, balancing, classification, computation, presentation, concept, application, rectification,
provision, analysis, conclusion — powers the "Weak spots & strengths" panel.
`pad` ∈ text | journal | ledger | tb | table | legal — chooses the writing-pad template (table builder, or the
Provision/Facts/Analysis/Conclusion starter).

### Blocks (used in concepts, illustrations, model answers)
| `t` | fields | validator checks |
|---|---|---|
| `p` / `note` / `wn` | `text` (`wn` also `title`: working note) | non-empty |
| `list` | `items[]` | non-empty |
| `journal` | `entries[{date, lines[{ac, dr}|{ac, cr}], narr}]`, `title`, `id` | every entry Dr = Cr |
| `ledger` | `ac, dr[{date, part, amt, bal?, ob?}], cr[…], next{date, side, amt}, from?, open?` | sides total equal; postings agree with journal `from` |
| `tb` | `date, rows[{ac, dr}|{ac, cr}], diff?` | totals agree (or differ by `diff`) |
| `cashbook` | `cols[], balanced[], dr[{date, part, lf, v[]}], cr[…], next` | balanced columns agree |
| `table` | `head[], rows[][], num[], total?, note?` | `total` row = sum of numeric columns |
| `legal` | `provision, facts, analysis, conclusion` | all four present |

### Numbers are computed, then re-checked
Unit sources use `Checks().add('80000*90/100', 'label')`; the value is stored with its expression and
`ca_validate.py` re-evaluates every `check`, every numeric MCQ (`check` must equal the keyed option and
no other option), every journal/ledger/trial-balance/cash-book/table total.

## Learning flow (per unit)
**Learn** (outcomes, ICAI topics, concept cards with analogy + real-CA-work) → **Examples** (try first,
then reveal the solution in exam format, with "figures machine-checked") → **On the job** (what a CA in
practice or industry actually does) → **MCQ** (Papers 3 & 4: exam-style +1/−¼; Papers 1 & 2: concept check)
→ **Write** (writing pad with timer, word count and table builder → model answer → self-marking with the
step-mark scheme → examiner remarks, common mistakes, presentation tips) → **Revise** (one page + quick ref).
Each tab marks itself done; a unit is complete when all six are. Home shows the next unit in ICAI order.

## Exam pattern used (from ICAI model test papers in the source folder)
Foundation P1 Accounting & P2 Business Laws: descriptive, 100 marks, 3 hours (P1: Q1 compulsory, any four
of the rest). P3 Quantitative Aptitude & P4 Business Economics: objective MCQs, 100 marks, 2 hours, ¼ mark
deducted per wrong answer.

## Progress data and future AI checking
Stored in `ST.ca` (localStorage `sv_state`): `level, exam, last, paper, units{uid:{learn,illus,job,mcq,write,revise,t}},
mcq{"uid#mid":{s,w,last,ms}}, writes{"uid#qid":[attempt…]} (last 5), group[]`, plus (js/ca-tools.js):
`mlog[[minute, "uid#mid", ok, secs]]` (last 1500 answers — accuracy & speed), `viva{"uid#vid":[{d,pct,hit[],secs,how,text}]}` (last 5),
`tests[{kind:'mcq'|'mock', d, title, pct, …}]` (last 80), `revise{"uid#mid":{d,n}}` ("Revise these"), `time{"YYYY-MM-DD":secs}`
(15-second heartbeat while the CA screen is visible and touched in the last minute), `notes{saved{}, hl{uid:[{ref,text}]}, mine{uid:{text}}}`,
`mockDraft{id:{secs, ans{}, tf{}, chosen[]}}` (resume a paper). The CA dashboard passes this to the shared engine through
`Insights.dashboardFor(host, {mode:'ca', data})` (adapter `insData` in js/ca-tools.js) and adds exam countdown, MCQ speed,
viva, mock history and unit progress; without the engine it draws its own version.
An attempt keeps the answer text (≤6000 chars), table rows, time, words, ticks per scheme point and
`status: "self"`. `Ca.submission(uid, qid)` returns the payload for a future backend checker:
```json
{ "schema": "ca-submission/1", "unit": "fnd-p1-ch02-u01", "question": "q1", "marks": 6,
  "answer": {"text": "…", "table": {"schema": "ca-pad/1", "sheets": [{"tpl": "journal", "name": "Journal", "title": "…", "data": {…}, "flat": {"cols": [...], "rows": [[...]]}, "check": {"ok": true, "msg": "…"}}]}},
  "self": {"score": 4.5, "ticks": {"s1": 1, "s2": 0.5}}, "meta": {"secs": 610, "words": 180, "date": "2026-11-07"},
  "status": "self" }
```
The checker can return `{status: "ai", score, ticks, remarks[]}` against the same `scheme` ids.
(Attempts saved before the templates keep the old `table: {cols, rows}` shape.)

## Writing-pad exam formats (js/ca-pad.js)
The Write tab's answer pad offers the formats a CA Foundation student writes, picked from the question's `pad` and its wording
(`CaPad.suggest(pad, q)` — e.g. "Prepare a three-column cash book" → three-column Cash Book; "Distinguish between" → comparison
table; a question that asks for a Trading A/c, P&L A/c and Balance Sheet suggests all three). A student can add several tables
to one answer. Formats (column layouts follow the ICAI study material): Journal, Journal Proper, Purchases Book, Sales Book
(each also with GST columns), Purchases Returns Book (Debit Note No.), Sales Returns Book (Credit Note No.), Bills Receivable Book,
Bills Payable Book, simple / two-column / three-column Cash Book, analytical Petty Cash Book (renameable analysis columns), Ledger
T-account (Date · Particulars · J.F. · Amount each side, "Balance it" → Balance c/d and the b/d line), Trial Balance (Particulars ·
L.F. · Dr · Cr), Bank Reconciliation Statement (start from either book, favourable or overdraft, Add / Less, check against the
balance given), Trading A/c, Profit and Loss A/c, Balance Sheet (horizontal and Schedule III Division I), Receipts and Payments A/c,
Income and Expenditure A/c, Statement of Affairs, Partners' Capital / Current A/cs (columnar, one column per partner), P&L
Appropriation A/c, Revaluation A/c, Realisation A/c, depreciation schedule, Asset / Provision for Depreciation A/c, stores ledger
(FIFO / weighted average), comparison table, blank table.
Conventions: dates dd-mmm-yy (05-Apr-26; ICAI-style 01-Apr-X1 accepted) with a date picker and validation; separate Dr. / Cr.
amount columns; account names in Title Case on leaving the cell (A/c, &, GST, CGST/SGST/IGST, LLP, BRS kept; joining words such as
"and", "for", "of" stay lower case as ICAI writes them — empty `SMALL` in js/ca-pad.js to capitalise every word); journal credit
lines "To … A/c" indented; narration "(Being …)"; Indian digit grouping; totals and a check per format (Dr = Cr, sides agree,
Schedule III totals agree, BRS reconciles, row totals in GST and petty cash books, qty × rate = amount, opening = last closing).

## Topic reference chips
Under every MCQ explanation (unit MCQs, case sets, MCQ builder, revise list, endless practice, group/daily sets), on question-bank
items and on mock-paper model answers the app shows `Paper 1 · Accounting › Ch 2 · Accounting Process › Unit 1 · … › Topic: …`
(`topic` of the MCQ, else the unit title; generated items use their unit + `concept`). Tapping it opens the unit's Learn tab and
scrolls to the concept card (by the MCQ's `concept` id, else the card whose title best matches the topic). Results screens group
accuracy by paper, chapter or topic and filter the review list the same way (`Ca._.refInfo / refChip / openRef`).

## Group study links
`#cau=<b64>` opens a unit · `#cagrp=<b64>` `{id, u, seed, n, s, ms, k}` plays the same MCQ set in the same
order (seeded shuffle) · `#cagrpr=<b64>` returns the friend's result. No server needed.
